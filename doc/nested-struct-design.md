# 表格嵌套结构字段设计（第五阶段 5.8）

日期：2026-11-15。状态：设计已定，按阶段实现，进度见文末。

## 目标

字段类型目前只能是内建类型或枚举。策划常见的“奖励 = 物品 + 数量”“多段消耗”只能拆成平行列（`RewardID`、`RewardCount`），各语言代码里也是散字段。本设计允许字段类型为另一个结构，并支持结构数组，导出到 JSON、Lua、各语言源码、专用二进制与 Protobuf。

## 类型表

不新增“种类”。任何用 `表头` 定义的对象类型都可以作为字段类型使用：

| 种类 | 对象类型 | 标识名 | 字段名 | 字段类型 | 数组切割 |
| --- | --- | --- | --- | --- | --- |
| 表头 | Reward | 物品 | ItemID | int32 | |
| 表头 | Reward | 数量 | Count | int32 | |
| 表头 | Item | 编号 | ID | int32 | |
| 表头 | Item | 奖励 | Reward | Reward | |
| 表头 | Item | 消耗 | Costs | Reward | `;` |

- 字段类型为结构名即为结构字段；`数组切割` 非空即为结构数组（结构数组不按切割符拆分单元格，只用来标记数组，与现有“非空即数组”的规则一致）。
- 结构可以嵌套结构，但不能直接或间接包含自身，否则报 `RecursiveStructField`。
- 结构字段不能建索引，也不能作为索引字段的一部分。
- 结构类型本身也可以同时是某张数据表的表头类型，互不影响。

## 数据表写法

结构成员展开成列，列头用“字段.成员”，字段与成员都可写字段名或标识名：

| 编号 | 奖励.物品 | 奖励.数量 | 消耗[1].物品 | 消耗[1].数量 | 消耗[2].物品 | 消耗[2].数量 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1001 | 5 | 2001 | 1 | 2002 | 3 |
| 2 | 1002 | 1 | 2001 | 2 | | |

- 多层嵌套继续加点：`奖励.附加.数量`。
- 结构数组用 `字段[序号].成员` 分组。序号只用于分组和排序：同一序号的列属于同一个元素，元素按序号从小到大排列，序号不要求连续。
- 某行一个元素的所有列都为空时，该元素不出现（上例第 2 行的“消耗”只有 1 个元素）。
- 结构成员本身是基础类型数组时，沿用现有写法：同名重复列，或单列按该成员的切割符拆分。
- 没有出现在列里的成员取默认值，和普通字段缺列时一样；结构字段的所有列都为空时导出默认值的结构（所有成员为默认值），结构数组为空数组。V3 不支持自定义默认值的原则不变。
- 同一结构字段既写 `奖励.物品` 又写整列 `奖励`，或者同一成员出现两次（同一序号内），报重复列。

选择展开列而不是单元格内联语法（如 `物品=1001;数量=5`）：展开列能逐格校验并在报错时指向具体单元格，Excel 筛选、排序也可用；也和已有 Proto 映射的 `reward.item_id` 路径写法一致。单元格内联写法作为第三阶段的可选扩展。

## 内部表示

- `HeaderField` 增加成员路径：列头解析为“表头字段 → 结构成员 → …”的路径，路径每一步可带数组序号；`TypeInfo` 仍指向叶子成员的定义，原有逐列的类型检查与报错位置不变。
- 合并后的输出表仍按表头类型的字段一列一格。结构字段的格子保存一个结构值（`Cell.Struct`），结构数组保存结构值列表（`Cell.Structs`）；结构值内部同样按结构的字段顺序一格一个 `Cell`，可递归。
- 合并时按路径把输入列的值放进对应的结构值，复用现有的单元格复制与数组合并逻辑；检查阶段递归检查每个叶子单元格。

## 各导出格式

| 格式 | 输出 |
| --- | --- |
| JSON（合并/分表） | 结构为对象，结构数组为对象数组，键按字段名排序，与现有行对象一致 |
| Lua | 结构为嵌套 table，结构数组为 table 数组 |
| Go | 结构字段为值类型 `Reward Reward`，结构数组为 `[]Reward` |
| C# / Java | 结构字段 `public Reward Reward = new Reward();`；结构数组 C# 为 `List<Reward>`，Java 为 `Reward[]` |
| Proto 源码 | 结构字段为对应 message，结构数组为 `repeated` |
| jsontype | 字段类型写结构名，并标记结构/结构数组 |
| 专用二进制 | 使用格式中已预留的结构标签（类型 11，数组 111）：长度前缀的子结构；C# `TableReader.ReadStruct` 已支持读取 |
| Protobuf 数据 | 嵌套 message / repeated message |

标签动作作用于结构成员的定义（例如 `nogenfield_json` 标记某个成员）。尚未支持结构字段的格式遇到结构字段时报 `StructFieldNotSupported` 并指出格式名，不会生成缺字段的数据。
